# Сквозная проверка — 18 октября 2026

## Окружение и изоляция

Проверка выполнена через интерфейс статического Next.js-фронтенда: два отдельных браузерных сеанса заказчика и мастера, реальный API, PostgreSQL, RustFS/S3 и ClamAV. Аккаунты и заказы созданы через формы, без подстановки записей в БД. Использованы вымышленные email на example.com и публичный PNG из проекта.

Для браузерной проверки выделены случайные тестовая схема и S3-бакет; основная база и перенесённые файлы не изменялись. Письма читались из development-email, внешняя доставка SMTP не проверялась. После проверки обе временные схемы и бакеты удалены; необработанных событий outbox не осталось.

## Пройденный сценарий

1. Гостевой заказ с фотографией: загрузка в S3, антивирусная проверка, ожидание подтверждения email. До подтверждения заказ отсутствует в каталоге.
2. Регистрация мастера по email, создание и публикация профиля со специализацией, регионом и аватаром.
3. Подтверждение email заказчика, публикация заказа и вход в аккаунт.
4. Поиск заказа, отправка приватного отклика с ценой и сроками; уведомление заказчику.
5. Выбор исполнителя, статус «В работе», двусторонняя переписка; уведомления без раскрытия текста сообщений.
6. Завершение заказа и два встречных отзыва. Отзыв заказчика обновляет публичный рейтинг мастера; повторной формы отзыва нет.
7. После завершения история сообщений доступна, отправка новых закрыта. Прочтение уведомления уменьшает счётчик.

Снимок итогового профиля: `frontend/e2e-profile-review.jpg`.

## Найденные и исправленные ошибки

- В публичной карточке своего заказа отображалась форма отклика. Теперь владение проверяется через приватный API; при ошибке проверки форма не открывается.
- Пустой список откликов заказчика ссылался сам на себя. Бесполезная ссылка убрана; переход на первую страницу при выходе за диапазон сохранён.
- После отправки отклика счётчик в карточке оставался прежним. Карточка перечитывается, подтверждение отправки сохраняется при обновлении.
- Письмо о новом отклике вело в сделку вместо списка откликов. Маршрут выбирается по типу уведомления; переписка и действующая сделка сохраняют свои адреса.
- HTTP-валидатор превращал пустой бюджет в ноль. Nullable-схемы бюджета, цены и сроков исправлены: `null` сохраняется, явный ноль цены допустим, нулевой срок отклоняется.

Первые три исправления повторно проверены в браузере. Для nullable-полей добавлены HTTP- и PostgreSQL-регрессии; после перезапуска изолированного API новый гостевой заказ без бюджета в браузере показал «По договорённости». Старые нулевые значения автоматически не изменялись.

- Интеграция: 30 тестов с PostgreSQL/S3/ClamAV, без пропусков — успешно.
