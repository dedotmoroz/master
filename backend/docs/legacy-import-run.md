# Загрузка локального снимка 2022 года

## Что загружено

Основной импорт выполнен 16.10.2026 в постоянную БД `naitimastera` на `127.0.0.1:55433`:

| Данные | Количество |
| --- | ---: |
| Аккаунты | 4 204 |
| Профили исполнителей | 3 214 |
| Заказы | 1 019 |
| Из них открыты в публичной выдаче | 684 |
| Сняты с публикации (draft) | 334 |
| С выбранным исполнителем (in_progress) | 1 |
| Рабочие отклики | 2 869 |
| Исходные предложения в истории версий | 3 137 |
| Исторические отзывы +1/-1 | 17 |
| Сообщения по предложениям | 465 |

Рабочий отклик представляет последнюю версию пары заказ/исполнитель (selected имеет приоритет). История включает и текущую версию, поэтому 2 869 и 3 137 не суммируются. Приватность каждого сообщения предложения сохраняется. Через GET `/api/v1/bids/:bidId/messages` доступны 462 достоверно связанных сообщения только двум собеседникам. Три сообщения без bidId сохранены в БД, но не выдаются. Для прежних версий предложений отдельного HTTP-метода пока нет. Правила — в [bid-messaging.md](bid-messaging.md).

По решению пользователя миграция `019_unified_review_rating.sql` включает старые отзывы в **общую** ленту и рейтинг: 2 положительных отзыва имеют оценку 5, 15 отрицательных — 2. Накопительные баллы старого сайта полностью исключены. `GET /api/v1/contractors/:contractorId/reviews` выдаёт новые и старые отзывы вместе, без разделения; у старых `orderId`/`orderTitle` равны null. Общий рейтинг каждого профиля — округлённое до 2 знаков среднее всех его опубликованных оценок. Отзывы со статусами hidden/disputed не считаются. Счётчик завершённых заказов от переноса отзывов не увеличивается. Проверены все 17 отзывов через API для 13 профилей.

Исходный знак сохранён внутри `legacy_profile_reviews.score` для происхождения и повторяемого импорта. Согласованная оценка хранится в вычисляемом `rating_score`; единое SQL-представление `reputation_reviews` отдаёт её как score. Профиль, каталог, сортировка, minRating и пагинация используют одно представление. Повторное применение миграций/импорта не преобразует 2 в другое значение и не добавляет дубликаты.

По подтверждённым правилам исключены 63 заказа, 86 откликов, 12 ссылок файлов заказов и 16 сообщений. Это включает отсутствующих владельцев, пустые описания, удалённые заказы, отсутствующих исполнителей, пустые отклики и зависимости. Исходные SQL и файлы сохранены.

В 2 заказах заголовок превышает 160 символов: рабочий заголовок ограничен, оригинал сохранён в `legacy_import_entities.metadata.originalTitle`. Профили со множеством специализаций сохранены целиком: лимит специализаций расширен с 20 до 50 в домене, HTTP и Swagger. Региональные заказы поддерживаются существующим ядром, город не придумывался.

Импорт не создаёт сессии, согласия пользователя или уведомления. Старые пароли и токены не копируются, административные права автоматически не назначаются. Удаление аккаунта также очищает связанные персональные данные миграции.

## Запуск с импортированными данными

`.env` переключён на постоянную БД 55433; старый тестовый PostgreSQL 55432 не пересоздавался и не удалялся. Уже запущенный процесс API надо перезапустить, чтобы он перечитал `.env`.

```bash
docker compose -f docker-compose.data.yml up -d --wait postgres storage clamav
npm start
```

Swagger: http://localhost:3000/docs/. Контейнеры данных используют именованные тома. Не выполняйте `docker compose -f docker-compose.data.yml down -v`: `-v` удалит данные. Обычная остановка/перезапуск не удаляет тома. Это локальная конфигурация, не защищённый production deployment; пароли здесь разработческие.

Основной импорт проверен через реальные HTTP-обработчики с новой БД: открытых заказов 684, профилей 3 214. Проверены атомарный rollback, повторный запуск без дублей/перезаписи, FK и отсутствие событий outbox/сессий. Сам импорт использует стабильные UUID и постоянные ID-соответствия.

## Повторяемые команды

```bash
npm run db:migrate
npm run legacy:audit
npm run legacy:import             # только валидация и расчёт
npm run legacy:import -- --apply   # атомарный импорт; завершённый снимок не загружается повторно
npm run storage:init
npm run legacy:files              # антивирус + обработка + S3 + связь с владельцем
```

Для основного импорта нового снимка требуется пустая БД. Завершённый снимок определяется SHA-256; повтор не восстанавливает удалённых пользователей и не перезаписывает последующие изменения. Отчёт `selection.mode=dry-run` описывает расчёт фильтра, фактическая запись подтверждается только `phase=committed` и записью `legacy_import_runs`.

## Файлы

Перенос завершён и проверен повторным запуском: **1 184 ready-вложения**, повтор не создал новых объектов/записей. Из них 418 файлов заказов, 765 аватаров и 1 изображение портфолио. Через реальный HTTP-обработчик получена подписанная ссылка и успешно скачан перенесённый объект. Потерянных ссылок заказов на файлы нет.

Пропущены 527 ссылок: 510 внешних/небезопасных путей, 15 неподдерживаемых или повреждённых файлов, 2 отсутствующих файла портфолио (включая пустую ссылку). Исходные файлы сохранены. Причины доступны в `legacy_file_import_results`, никаких внешних URL процедура не запрашивала.

Перенос файлов выполняется отдельно и может продолжаться после основного импорта. Изображения и PDF сначала проверяются реальным ClamAV, изображения преобразуются в WebP с удалением метаданных. Разрешены только распознанные растровые форматы и PDF, проверяются лимиты размера, локальность пути и запись в S3. Без работающего антивируса процедура завершается ошибкой, ready-записи не создаются. Внешние аватары, отсутствующие файлы и неподдерживаемые форматы не публикуются.

Успешные результаты и причины пропусков сохраняются в `legacy_file_import_results`; SHA-256 оригинала/обработанного объекта — в metadata ID-соответствия. Повтор пропускает уже готовые вложения. Оригинальные файлы старого сайта не удаляются. Для уже изменённых профилей импорт не заменяет пользовательский аватар.

Внимание: основной импорт и перенос файлов — две отдельные процедуры. Завершение первого не означает, что все файлы стали доступны; состояние второго проверяется по `phase=files-complete` и таблице результатов.

## Резервная копия до переноса

До начала работ сохранена резервная копия первоначальной новой тестовой БД: `backups/pre-legacy-W2EVbU/database.dump`. После завершения переноса сохранена заполненная постоянная БД: `backups/pre-legacy-W2EVbU/after-import.dump` (2,7 МБ, custom pg_dump). Каталог архива читается `pg_restore --list`. Каталог исключён из Git, доступ к файлам ограничен владельцем. Эти копии не заменяют регулярный backup новой постоянной БД и S3. В after-import.dump хранятся строки БД и ссылки на объекты, а сами S3-объекты — в постоянном томе RustFS; оригиналы доступны в дереве старого сайта. Исходный MySQL-дамп остаётся отдельной исходной копией.
